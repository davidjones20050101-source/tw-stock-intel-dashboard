先建立正確心智模型

Codex 不是聊天機器人，是工程協作 Agent

📖

讀懂專案

它可以閱讀程式碼、文件、開啟的檔案與專案規則，先理解再提出計畫。

Prompt 基礎

第一個任務要怎麼下？

好任務包含 5 件事

  • 目標：要解決什麼問題
  • 範圍：可改與不可改的地方
  • 驗證：要跑哪些測試
  • 輸出：要回報什麼
  • 限制：安全、語氣、風險
請先閱讀這個專案，找出登入流程。 目標：修正手機版登入按鈕被遮住的問題。 範圍：只改 frontend/login 相關檔案。 驗證：完成後執行 npm run lint 與 npm test。 輸出：請列出修改摘要、測試結果、風險與需要人工確認的地方。

Cloud 入門

什麼時候該用 Codex Cloud？

適合丟雲端

重構、補測試、升級套件、修 CI、整理文件、處理 backlog issue。

不適合直接丟

未定義清楚的產品方向、需要即時互動的 UI 微調、涉及機密或高風險部署。

最大優勢

可以讓多個任務平行跑，每個任務在隔離環境中完成，回來看結果。

最大風險

任務寫太模糊時，會產出看似完整但方向錯的改動。

專案規則

AGENTS.md：讓 Codex 照你的規矩做

一定要寫的內容

  • 專案架構與重要資料夾
  • 安裝、測試、build 指令
  • 程式風格與命名規則
  • 禁止修改的檔案
  • 完成回報格式
# AGENTS.md 範例 - 回覆一律使用繁體中文。 - 修改前先讀 README 與 package.json。 - 前端修改後必跑：npm run lint && npm test。 - 不可修改 .env、金流設定、正式 DB migration。 - 完成時列出：變更摘要、測試結果、風險、回滾方式。

進階但很重要

Skills、Plugins、MCP 是什麼？

📦

Skills

把固定 SOP 包起來，例如「產生 dashboard」、「做 code review」、「轉成繁體中文教學稿」。

🔌

Plugins

把工具接進 Codex，例如任務系統、文件庫、部署平台。

🧰

MCP

讓 Codex 用外部工具與資料，但必須控權限、輸出長度與可審核性。

給新手的理解：AGENTS.md 是規矩，Skills 是 SOP，Plugins/MCP 是工具箱。

權限模式

安全使用 Codex 的 4 層邊界

層級你要決定什麼新手建議
讀取哪些檔案可以讓 Codex 看先排除 .env、金鑰、客戶資料。
寫入哪些資料夾可以改先限制在功能資料夾，不要全專案放開。
命令哪些 shell 指令能跑測試可放寬；部署、刪除、migration 要人工批准。
網路是否能查外部文件或下載套件需要時才開，並避免未審查的供應鏈風險。

審查流程

不要只看 Codex 說「完成了」

①

看摘要

確認它做的是你要的。

②

看 diff

逐檔檢查關鍵修改。

③

看測試

確認測試真的有跑且通過。

④

看風險

要求列出沒驗證到的部分。

追問模板： 請列出這次修改最可能出錯的 3 個地方。 哪些情境你沒有測到？ 如果我要回滾，應該還原哪些檔案？

ChatGPT 隱藏能力如何搭配

先把素材變清楚，再交給 Codex

圖片 / 截圖

把錯誤畫面、UI 跑版、架構圖當上下文，讓 Codex 不只靠文字猜。

檔案 / 文件

上傳規格、API 文件、錯誤 log，請它先整理需求與驗收條件。

搜尋 / 最新文件

遇到新框架、新套件、新 API，先查官方文件，再要求產生改法。

專案 / 記憶

把常用規則固定下來，減少每次重講背景的成本。

這一頁對應補充影片的精神：善用 ChatGPT 的多種上下文能力，讓 Codex 收到更完整的任務資訊。

新手練習路線

7 個練習，從簡單到實戰

  • 練習 1請 Codex 解釋一個檔案，不修改。
  • 練習 2請它找出可能的 bug 與測試缺口。
  • 練習 3限定一個檔案，修小 bug。
  • 練習 4補單元測試並跑測試。
  • 練習 5請它 review 你自己的改動。
  • 練習 6把一個小 issue 丟到 Cloud。
  • 練習 7寫 AGENTS.md，讓下次任務更穩。

落地清單

第一週導入 Codex，照這樣做

  • 第 1 天：選一個低風險 demo repo，請 Codex 只做理解與摘要。
  • 第 2 天：用 IDE 修一個小 bug，要求先提方案再修改。
  • 第 3 天：用 CLI 跑 edit → test → diff 的完整流程。
  • 第 4 天：建立 AGENTS.md，固定測試指令與禁止事項。
  • 第 5 天：把一個 backlog issue 丟到 Cloud，回來做 code review。
結論：新手導入 Codex，不是追求一開始就全自動，而是先建立「小任務、明確邊界、可驗證交付」的習慣。
